# Glossa — project context for AI agents

Ты продолжаешь разработку проекта Glossa — платформа для изучения языков (React 18 + Vite 5 +
Tailwind v4 на фронте, FastAPI + Django на бэке). Репозиторий:
C:\Users\user\Desktop\Softclub\Python Courses\Python 5\Exams\Glossa
Один git-репозиторий на корне, покрывает и Backend/, и Frontend/.

## Архитектура бэкенда (важно, часто путают)

- FastAPI (порт 8000, `Backend/app`) — истории, грамматика, подписки, кошелёк и т.д.
- Django `auth_service` (порт 8001, `Backend/auth_service`) — ОТДЕЛЬНЫЙ сервис, тут регистрация,
  логин, JWT, 2FA. Если регистрация фронтенда падает с "No connection to the server" — почти
  всегда значит, что этот Django-сервис на 8001 просто не запущен, это не баг фронта.
- FastAPI websocket (порт 8002, `Backend/websocket_app`) — чат с ИИ-репетитором.
- БД — Postgres как НАТИВНАЯ служба Windows (`postgresql-x64-18`) на `127.0.0.1:5432`. Сервис
  `postgres` внутри `Backend/docker-compose.yml` — не тот, к которому реально подключается
  приложение, не пытайся поднимать его в докере, это не нужно и будет путать.
- Redis — единственный сервис, который реально нужен из docker-compose (`docker compose up -d
  redis` из `Backend/`).
- В `Backend/` есть venv (`Backend/.venv`) — все три Python-процесса запускаются через него
  напрямую (`uvicorn app.main:app --reload --port 8000`, `uvicorn websocket_app.main:app
  --reload --port 8002` из `Backend/`, `python manage.py runserver 8001` из
  `Backend/auth_service`). НЕ гоняй `django_app`/`fastapi_main`/`fastapi_websocket` сборку через
  docker — в этом окружении Docker Hub жёстко троттлит скачивание больших слоёв (~18KB/s), сборка
  образов может висеть часами. Postgres/redis из docker-compose тянутся нормально, кэшированные
  образы — тоже.

## Быстрый запуск всего окружения одной командой

В корне репозитория лежит `start-glossa.ps1` (+ `start-glossa.bat` для запуска двойным кликом) —
поднимает Postgres-службу, Docker Desktop, Redis, оба FastAPI-процесса, Django `auth_service` и
фронтенд одной командой, с проверкой уже занятых портов (повторные запуски безопасны). Эти два
файла в `.gitignore` специально (по просьбе владельца), их не будет видно через `git log` —
просто знай, что они есть на диске, и используй `.\start-glossa.ps1` для старта разработки.

- React 18 + Vite 5 + Tailwind v4, дизайн-система "Neo-Retro Editorial" (кремовый фон, малиновый

  (Landing/About/FAQ/Privacy/Terms/Contact) пересобраны один-в-один под этот референс, с
  реальными данными тарифов из `GET /subscriptions/plans` (без авторизации, валюта — сомони/TJS,
  не доллары). Авторизованные страницы приложения (Dashboard, Settings и т.д.) в этот заход не
  проверялись — не считай их автоматически покрытыми теми же тремя языками/тёмной темой без
  проверки.

## Правила работы, которые важны владельцу

- Коммитить нужно от его имени (git config уже настроен на его identity), без каких-либо
  AI-меток в коммитах (никакого "Co-Authored-By"). Коммитить можно и нужно без лишних вопросов,
  но только локально: `add`/`commit`/`branch`/`log` — можно, `push`/PR/`gh` CLI — категорически
  нет, всё, что уходит на GitHub, он делает сам.
- Планы делать пошагово: один пункт плана — один коммит, останавливаться и ждать подтверждения
  перед следующим шагом, а не гнать весь план разом.
- Прежде чем говорить "готово" — проверять весь реальный пользовательский путь целиком (например
  register → verify → login → protected page), а не один изолированный API-запрос. Для проверки
  UI — accessibility snapshot / curl / сборка, НЕ скриншоты (владелец их не хочет).
- Не трогать `Backend/` без явного запроса на это — только если задача прямо про бэкенд.

Начни с чтения `Backend/progres.md` (хвост файла) и `Frontend/Plan/design/` (если задача про
фронтенд), чтобы понять, где реально остановилась работа, прежде чем планировать следующий шаг.
